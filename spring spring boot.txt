                Q6. Why do we even need maven ?
                         - when we write core java programs,we usually deal with just few .java files. however once we enter the world of enterprise applications 
                           like,spring and spring boot we rely on hundreds of classes provided by - framework, third-party libraries, external tools 
                           so we can't write all of these ourselves. we reuse them.
                         - Before Maven :
                                    - Developers had to manually search the internet for jar files like spring-web.jar, mysql-connector.jar, jackson.jar....
                                    - Download them one by one
                                    - Place them inside a folder like lib/
                                    - Add them manually to the classpath
                                    - if one jar depends on 10 more jars then more downloading.
                                    - also every developers in a team had to repeat the same painful steps.
                                    - Maven Automates all of this.
                Q7. What is maven ?  
                         - Maven is a Build Automation and Dependency Management Tool. 
                         - It automates compilation, testing, packaging, and dependency management etc..
                Q8. What is POM in Maven?   
                         - POM (Project Object Model) is an XML file (pom.xml).
                         - it contains the project's configuration,dependencies, plugins, and build information.
                Q9. What is the difference betwen pom.xml file and application.properties file ?  
                         - pom.xml build time configuration(build process, dependencies, plugins) hai aur 
                         - application.properties runtime configuration(database, server, logging, etc.) hai.
                Q10. Maven kaise identify krta hai ki kaunsi dependency download krni hai ?

                Q12. What is difference between starter and transitive dependency ?  
                         - Starter dependency → jo tum khud pom.xml me add karte ho. 
                         - Transitive dependency → jo starter (ya kisi aur dependency) ke through automatically aa jati hai. 
                         - eg- spring-boot-starter-web = Starter Dependency (directly added by you). spring-web, spring-webmvc, jackson-databind, tomcat-embed-core etc. = Transitive Dependencies (automatically pulled)
                Q13. Where does maven download from ?
                         - Maven first checks the local repository (~/.m2/repository).
                         - If the dependency is not found locally, Maven downloads it from the Maven Central Repository / remote repository.
                         - After downloading, Maven stores it in the local repository so it doesn't need to download it again.

                Q19. Explain common used maven commands ? 
                         - mvn clean :
                                 - remove old compiled files / deletes the target folder.
                                 - to avoid conflicts with older builds.
                                 - to ensure a fresh start.
                         - mvn validate :
                                 - check if our project is correctly configured like,
                                 - is Pom.xml valid xml?
                                 - are all required fields (groupId,artifactId,version) present ?
                                 - is the project structure correct ?
                                 - are all necessary plugins available ?
                         - mvn compile :
                                 - compile our java source code
                                 - this reads files from src/main/java and generate .class files into target/
                         - mvn test : 
                                 - runs all unit tests.
                         - mvn package :
                                 - package the project into jar or war
                                 - output is generated in the target folder (target/myapp-0.0.1-snapshot.jar)
                                 - this is the file we can run or deploy.
                         - mvn verify : 
                                 - it builds your project,tests it, and verifies everything is working without actually deploying it.
                                 - if something fails, it will let you know.
                         - mvn install :
                                 - common command / most important
                                 - it compiles -> tests -> packages -> verify and then install the final .jar into local maven repository(.m2 folder).
                                 - this allows other pojects on your machine to reuse it.
                         - mvn deploy :
                                 - upload your project's jar/war file to a remote maven repository(Nexus,Artifactory) for sharing with other developers/projects.
                                 - To deploy artifacts to a remote repository, you typically configure the <distributionManagement> section in pom.xml and provide repository credentials in settings.xml.
                         - mvn site :
                                 - used to generate a project documentation website for a maven project automatically.
                                 - it takes information from your project(POM,reports,Dependencies,plugins,test,coverage,etc.) then creates a HTML documentation site you can open in a browser.

                Q25. What is Inversion of control ?  
                         - Ioc is a software design "principle". that define how objcts are created and managed in a program. 
                         - itself doesn't create the object but provide way for it.
                         - with IOC, the control flow of the program is reversed.
                         - instead of the programmer,the responsibility of creating and managing objects is transferred to the IoC container.
                Q26. What is Dependency Injection & it's advantages ?  
                         - DI is a design 'pattern' used to implement IOC
                         - the approach reduces coupling between objects by allowing the framework to dynamically provide the required dependencis at runtime.
                         - Advantages :
                                     - loose coupling between components
                                     - minimize the ammount of code
                                     - makes unit testing easy with different mocks
                                     - increase system maintainability & module reuseability
                                     - allow concurrent and independent development
                                     - replacing modules has no side effect on other modules.
                Q27. What is a Spring Bean?   
                         - A Spring Bean is an object that is created, configured, and managed by the Spring IoC container.
                Q28. Why Called Bean in spring ?

                         - To differentiates them, the objects managed by Spring are called Spring Beans.

                Q32. Difference between BeanFactory and ApplicationContext ?

                                                 Bean Lifecycle Management : Bean initialize aur destroy callbacks manage karta hai.

                Q3. How does Spring decide which bean to inject? 
                         - By Type (Default) :
                                       - Spring first searches for a bean of the required type.
                         - By Qualifier / Bean Name :
                                       - If multiple beans of the same type exist, Spring looks for @Qualifier (or bean name if applicable).
                         - @Primary :
                                       - If one bean is marked with @Primary, Spring injects that bean by default.
                         - Exception :
                                       - If Spring still cannot determine a single bean, it throws NoUniqueBeanDefinitionException.

                Q6. Explain @Primary annotation ?  
                                   - when multiple beans of the same type exist in the spring context,you can mark one as default by using the @Primary annotation.
                                   - the primary bean is the one spring will automatically select when multiple candidates are available and no specific bean name is provided.
                Q7. Explain @Import annotation ?  
                                   - @Import allows one @Configuration class to include bean definations from another configuration class.

                                   - Spring Boot automatically bahut saari configuration kar deta hai. because @EnableAutoConfiguration internally @Import ka use karta hai auto-configuration classes ko import karne ke liye.
                Q8. Explain @Component and @ComponentScan annotation ?    
                                   - @Component: 
                                          - it is Stereotype = (Label / Tag / category) annotation.
                                          - it simplyfies the process of creating and registering a bean in the spring context with minimal code. 
                                   - @ComponentScan : 
                                          - it is used to ensure spring scans and registers these(@Component,@Service, @RestController) annotated classes . 
                                          - most commonly used with @Configuration classes to define component scanning rules. 
                                          - eg: @ComponentScan("com.example.service").
                Q9. Explain @PostConstruct and IntializingBean Interface ?
                                   - @PostConstruct is a spring annotation used to run a method automatically after a spring bean is created and its dependencies are injected.
                                   - it runs only once in the bean's lifecycle.
                                   - @PostConstruct is used :
                                                       - to perform setup logic when a bean is created.
                                                       - to load data, set default values or execute startup logic.
                                                       - to initialize resources after dependency injection. 
                Q10. Explain @PreDestroy and DisposableBean Interface ?
                                   - @PreDestroy is a spring annotation used to run a method automatically before a spring bean is destroyed.right before spring container shut down.
                                   - it runs only once in the bean's lifecycle.
                                   - @PreDestroy is used :
                                                       - to perform cleanup logic before a bean is destroyed.
                                                       - to close resources such as database connection,file handles etc. 
                                                       - to log or notify that the bean is being shut down. 
                Q11. Exaplain @Bean vs @Component ?   
                                   - @Bean :
                                        - one or more instances of the class can be added to the spring context.
                                        - we can create object instance of any type of class including present inside libraries like spring etc.
                                        - developer will have full control in creating and configuring the bean.
                                   - @Component :
                                        - only one instance of the class can be added to the spring context.
                                        - we can create object instance for application class only which are created by Developer team.
                                        - developer will not have any control in creating and configuring the bean.
                Q12. Explain Spring stereotype annotation : 
                                   - @Component :  
                                          - @Component is a generic stereotype annotation used to mark a class as a Spring-managed bean.
                                   - @Service :
                                          - @Service is used to mark a class that contains business logic as a Spring-managed bean.
                                   - @Repository :
                                          - @Repository is used to mark a class responsible for data access and database operations as a Spring-managed bean.
                                          - It also enables Spring's exception translation mechanism for persistence exceptions.
                                   - @Controller :
                                          - @Controller is used to mark a class as a Spring MVC controller that handles web requests and returns a view (such as a JSP or Thymeleaf page).
                                   - @RestController :
                                          - @RestController is used to mark a class as a REST controller that handles HTTP requests and returns the response body (typically JSON or XML).
                                          - it is combination of @Controller and @ResponseBody.

                Q18. What is Circulare Dependency and how to resolve it ?

                              - How To Resolve :
                                       - Redesign the classes :
                                                          - Break the circular dependency by changing the design.
                                                          - eg:  instead of : A ---> B ---> A     do   A ---> C <--- B.
                                       - Use @Lazy :
                                                          - Delay the creation of one dependency.
                                       - Use Setter Injection :
                                                          - Instead of constructor injection

                                              - create tables on startup,drops them on shutdown.
                                              - use case => unit tests, in-memory DBs.
                                         create-only :
                                              - only create schema,no dropping.
                                              - use case => initial migrations or clean tables.
                                         drop  : 
                                              - drops all tables.
                                              - use case => rare,mostly for tools or scripted cleanup.
                                         none :
                                              - hibernate will not manage the schema.
                                              - use case => production(recommended)
                                         truncate :
                                              - deletes all the row but keeps table structure.
                                              - use case => resetting test data without dropping tables.
                                         update :
                                              - update schema if necessary(add columns,tables).
                                              - use case => Development only
                                         validate :
                                              - check if DB schema matches entities.no change mode
                                              - use case => staging/prod

                Q1. What is Relationship in JPA?
                            - JPA Relationship is a mapping between two entity classes that represents how the corresponding database tables are connected 
                              using foreign keys.
                Q2. Benefits of JPA Relationships
                            - Maintains data consistency.
                            - Represents foreign key relationships.
                            - Reduces manual JOIN queries.
                            - Easy navigation between entities.
                            - Supports cascading operations.
                            - Supports lazy/eager loading.
                Q3. How many types of relationships spring data JPA supports give real time example of each one?
                            - Spring Data JPA supports 4 types of relationships.
                                    JPA Relationship Mapping
                                    │
                                    ├── One-to-One (1:1)
                                    │   └── One entity is associated with one other entity.
                                    │
                                    ├── One-to-Many (1:N)
                                    │   └── One entity is associated with multiple entities.
                                    │
                                    ├── Many-to-One (N:1)
                                    │   └── Multiple entities are associated with one entity.
                                    │
                                    └── Many-to-Many (N:N)
                                        └── Multiple entities are associated with multiple entities.
                Q4. What are the different mapping directions in JPA?
                            - There are two types of mapping directions:
                                    Mapping Direction
                                    │
                                    ├── Unidirectional
                                    └── Bidirectional
                            Note:
                                - saare 4 relationship types ko Unidirectional aur Bidirectional dono tarike se implement kiya ja sakta hai.
                                - JPA sirf entity references dekhkar samajhta hai. Unidirectional hai ya Bidirectional.
                            - UNI-DIRECTIONAL :
                                       - A Unidirectional Relationship means only one entity knows about the other entity, while the second entity has no reference back.
                            - BI-DIRECTIONAL :
                                       - Both entities (company and Job) know about each other.
                                       - you can navigate the relationship in both directions :
                                                             - from company,you can get all its jobs(company.getJobs()). 
                                                             - from jobs, you can get the company it belongs to (job.getCompany()).
                                                             - its like 2 friends both have each other phone numbers they can call each other anytime.
                Q5. Who owns the Relationship ?
                            - The Owner Side of a relationship is the entity that contains the Foreign Key (FK).
                            - In a One-to-Many / Many-to-One relationship, the Child Entity usually contains the Foreign Key, so it becomes the Owner Side.
                            - The Owner Side is responsible for managing and updating the relationship in the database.
                            - The other entity is called the Inverse Side (Non-Owning Side) because it does not contain the Foreign Key.
                            - The Inverse Side uses the mappedBy attribute to indicate that the relationship is already managed by the Owner Side. It takes the Owner Side's relationship field name (property name) as its value.
                            - Using mappedBy prevents duplicate relationship mappings and unnecessary join tables.
                Q6. What are cascade and it types in JPA?
                            - What :
                                   - if i do something to the parent entity,automatically do it to the child entity too.
                                   - it is commonly used on the Parent Side (such as @OneToMany).
                            - Why Do We use Cascade :
                                   - to avoid boilerplate code.
                                   - to avoid manually saving/deleting related entities.
                                   - to keep entities in sync automatically.
                            - Cascade Types :
                                   - PERSIST => save the child entity when the parent is saved.
                                   - MERGE  => update the child entity when the parent is updated.
                                   - REMOVE => Deletes the child entity when the parent is deleted.
                                   - REFRESH => refreshes the child entity when the parent is refreshed from DB.
                                   - DETACH  => detaches the child from the persistence context when parent is detached.
                                   - ALL    => applies all above actions.
                Q7. What is the meaning of Orphan and what are the state of orphanRemoval in JPA? 
                            - ORPHAN :
                                      - Jab koi child entity apne parent se unlink/remove ho jati hai, aur ab uska koi parent nahi bacha - usko orphan kehte hain.
                            - orphanRemoval :
                                      - if a job is removed from the list {Java Collection (List, Set, etc.)}, deletes it from the database also.
                                      - eg : company.getJobs().remove(job);
                                      - now the job is automatically removed -> clean database, no garbage data. 
                                      - orphanRemoval is always used on the Inverse Side, which is typically the Parent Side (@OneToMany).
                            - orphanRemoval has two states:
                                      - orphanRemoval = false (Default) → The job is removed from the collection, but the record still exists in the database.
                                      - orphanRemoval = true → The job is removed from the collection and its database record is automatically deleted.
                Q8. What are fetchtypes in JPA ?
                            - fetch types define when related entities are loaded from the database.
                            - when you define relationship like @OneToOne, @OneToMany, @ManyToOne, @ManyToMany, JPA needs to know :
                                                               - should the related data be loaded immediately when the parent is loaded ?
                                                               - or should it be loaded later, only when needed ?
                                                               - that's where fetch = FetchType.LAZY or FetchType.EAGER come in.
                                                               | Fetch Type |           Meaning               |             Behavior                       |
                                                               |------------|---------------------------------|------------------------------------------- |
                                                               | EAGER      | Fetch immediately               |  loads the related entity right away       |
                                                               |------------|---------------------------------|--------------------------------------------|
                                                               | LAZY       | Fetch when accessed (on demand) |  loads the related entity only when used.  |
                            - Default fetchtypes supported by mappings :
                                           Relationship Annotation        Default Fetch Type
                                           -------------------------------------------------
                                            @OneToOne                      EAGER
                                            @ManyToOne                     EAGER
                                            @OneToMany                     LAZY
                                            @ManyToMany                    LAZY

                Q9. What is the meaning of optional=false ?
                            - optional = false is an attribute of the @ManyToOne and @OneToOne annotations.
                            - It indicates that the relationship is mandatory, meaning the associated entity cannot be null.
                            - optional = false vs nullable = false :
                                    - optional = false → JPA level par relationship mandatory hai.
                                    - nullable = false → Database level par foreign key column NULL allow nahi karega.

                Q10. Explain @JoinColumn annotation ?
                            - @JoinColumn is a JPA annotation.
                            - It is used to specify the foreign key column that manages the relationship between two entities.
                            - It defines the name and properties of the foreign key column in the database.
                            - It is commonly used with @ManyToOne and @OneToOne relationships.
                            - @JoinColumn is always used on the Owner Side of the relationship, because the Owner Side contains the foreign key.

                Q11. What is @OnDelete(action=OnDeletion.CASCADE) annotation ?
                            - @OnDelete is an annotation in hibernate/JPA.
                            - it tells the database to automatically delete related records when a parent record is deleted.
                            - @OnDelete is used on the Owner Side of the relationship.
                            - Values supported by OnDeleteAction :
                                       NO_ACTION :
                                               - Default behavior,if a parent is deleted while children still exist,
                                                 the database raises a foreign key constraint violation(maybe later in transaction).
                                       CASCADE  :
                                               - Automatically deletes the child rows when the parent row is deleted.
                                       RESTRICT :
                                               - Immediately blocks the deletion of the parent if any child exists(strict than NO_ACTION)
                                       SET_NULL :
                                               - sets the child's foreign key to null when the parent is deleted(child remains,but unlinked)
                                       SET_DEFAULT : 
                                               - sets the child's foreign key to its default value(if any) when the parent is deleted.

                Q12. Difference between @OnDelete VS CascadeType.REMOVE ?
                                 | Feature       |                 @OnDelete                      |             CascadeType.REMOVE           |
                                 |---------------|------------------------------------------------|------------------------------------------|
                                 | Where it runs | Database level (SQL foreign key)               | Application level (Hibernate/JPA)        |
                                 | How it works  | Database deletes child records automatically   | Hibernate delete child records in code   |
                                 | Performance   | Faster (database handle it)                    | Slower (hibernate queries each record)   |
                                 | Code example  | @OnDelete(action = OnDeleteAction.CASCADE)     | @OneToMany(cascade = CascadeType.REMOVE) |
                                 | When to use   | When you want database to manage deletions     | When you need app-level control          |
                           NOTE: 
                              - @OnDelete is a database rule
                              - CascadeType is a hibernate instruction.

                Q1. What are Data Security / Data Privacy / Data Protection techniques ? 
                    - There are three common techniques used for data security and data protection:
                         - Encoding:
                                  - Used to convert data into another format for transmission or compatibility.
                                  - It is not a security mechanism.
                                  - Encoding is reversible through decoding.
                                  - Example: Base64 Encoding. It is commonly used to send binary data (such as images or files) over text-based protocols like JSON
                         - Encryption:
                                  - Used to protect sensitive data by converting it into an unreadable form using a key.
                                  - Encryption is reversible through decryption with the correct key.
                         - Hashing:
                                  - Used to securely store passwords and verify data integrity.
                                  - Hashing is irreversible; it is a one-way function and cannot be unhashed.

                Q3. What are the loop holes, in hashing protection techniques ?
                         - Some users choose weak and common passwords such as 123456 or password. It is also possible that multiple users use the same password.
                         - If an attacker gets access to the hashed passwords stored in the database, they can perform a brute force attack or rainbow table attack 
                           to guess the original passwords. 
                         - Since hash functions are designed to be fast, attackers can try millions of password guesses per second, making brute force attacks more effective.

                Q4. What is brute force attack ?
                         - A brute force attack is a trial-and-error method used by hackers to decode encrypted data, such as passwords or encryption keys. 
                         - In this type of attack, the attacker systematically tries all possible combination Of characters until the correct one is found. 
                         - It's essentially like trying every possible key in a lock until the right one opens it.

                Q1. What is Rainbow table / dictionary table attack?
                         - A rainbow table or Dictionary table attacks are a type of cryptographic(techniques used to secure data, such as hashing and encryption) 
                           attack used to crack password hashes.
                         -  It involves precomputing and storing a large number of password hashes along with their corresponding plaintext passwords in a table 
                            known as a "rainbow table" or a "dictionary table"

                Q5. How to prevent rainbow table attack ?
                         - To prevent rainbow table attacks, salts are commonly used. 
                         - Salts are random values that are unique for each user and are made public. 
                         - The salt value is stored as part of the resulting hash itself.
                         - Specifically, the salt is included in the hash string along with the actual hashed password.
                         - The salt is typically stored at the beginning Of the hash string and is used during the password verification process to generate the same
                           hash again for comparison. 
                         - Since each user has a unique hash function, attackers can't precomput arge tables Of passwords (rainbow tables) to test against the entire
                           database of stolen password hashes.
                         - eg : Plain text password + Random salt value + Hashing Algo = Strong Hash Value
                         - Spring Security provides industry recommended Password Encoders that are capable of generating random salt and leverage password hashing
                           algorithms like bcrypt

                Q1. What are Derived Query Methods ?
                         - Derived query methods are auto-generated queries based on method names in Spring Data JPA.
                         - Instead of writing SQL queries manually, you just name a method in your repository, and Spring Data JPA will automatically figure out the 
                           query for you.
                         - How Do Derived Query Methods Work :
                             - Spring Data JPA understands method names and automatically generates queries based on specific keywords in the method name.
                             - For example,
                                          Optional<Company> findByStatus (Strung status);
                                          for above method spring will automatically generate this query :  SELECT * FROM companies WHERE status = ?  ;
                         - A derived query method in Spring Data JPA consists of two main components separated by the first 'By' keyword:
                               - Introducer Clause :
                                      - This part specifies the type of operation to be performed on the database.
                                      - Common introducers include :
                                                                     find, 
                                                                     read, 
                                                                     query,

                Q19. What is cross-site request forgery (CSRF) ? 
                          - CSRF (Cross-Site Request Forgery) ek web security attack hai. (Forgery = Fake)
                          - jisme attacker kisi logged-in user se bina uski permission ke website par unwanted action karwa deta hai. instead of directly stealing the user's identity.
                          - How CSRF works :
                                        - User website me login karta hai.
                                        - Browser session cookie (e.g., JSESSIONID) save kar leta hai.
                                        - User kisi malicious website par jata hai.
                                        - Malicious site target website ko request bhejti hai.
                                        - Browser automatically cookie attach kar deta hai.
                                        - Website browser dwara automatically bheji gayi session cookie ko dekhkar request ko authenticated user ki request maan leti hai.
                                        - eg :
                                                   <form action="https://netflix.com/changeEmail" method="POST"  id="saveForm">
                                                       <input type="hidden" name="email" value="user@evil.com">
                                                   </form>
                                                   <script>
                                                          document.getElementById("saveForm").submit();
                                                   </script>
                          - How CSRF Token Validation Works :
                                Step 1 :
                                      - User website me login karta hai.
                                      - Server session create karta hai.
                                      - Server ek random CSRF token generate karta hai. like,  CSRF Token = A1B2C3
                                Step 2 :
                                      - Server generated CSRF token ko apni side par maintain karta hai (e.g., HttpSessionCsrfTokenRepository ya CookieCsrfTokenRepository ke through). like, CSRF Token = A1B2C3
                                      - Browser ko bhi same token bheja jata hai:
                                                                     • Hidden Form Field
                                                                     • Response Header
                                                                     • Meta Tag
                                                                     • Cookie (XSRF-TOKEN) like, CSRF Token = A1B2C3
                                Step 3 :
                                      - Browser automatically session cookie attach karta hai aur CSRF token ko Header ya Form Parameter ke through bhejta hai. :
                                                                                   like,    Cookie :  JSESSIONID = XYZ123
                                                                                            Header :  X-CSRF-TOKEN = A1B2C3
                                                                                                          ya
                                                                                                Form Parameter :  _csrf = A1B2C3
                                Step 4 :
                                      - Server request receive karta hai.
                                      - Server apni repository (Session/Cookie Repository) se expected CSRF token nikalta hai.. 
                                                                  Expected Token :   A1B2C3
                                      - Request se received token nikalta hai.
                                                                  Received Token :  A1B2C3
                                      - Dono compare kiye jate hain.
                                                                  A1B2C3 == A1B2C3   ✓ Request Valid
                                      - Agar token match nahi hua :
                                                                  A1B2C3 != XYZ999  ✗ 403 Forbidden
                                - This process is called CSRF Token Validation (or CSRF Token Verification)..
                          - Why does the attack fail :
                                           • Browser automatically sends the session cookie.
                                           • But the attacker cannot know or generate the correct CSRF token.
                                           • Therefore the server detects the mismatch and rejects the request with 403 Forbidden.

                Q20. What is the solution to CSRF attack?
                          - CSRF attacks are prevented by ensuring that every state-changing request contains a unique, unpredictable CSRF token that is validated 
                            by the server before processing the request.
                          - How to disable CSRF protection :
                                   - By default, Spring Security enables CSRF protection for all state-changing HTTP requests such as POST, PUT, DELETE, and PATCH.
                                   - If an application does not require CSRF protection (e.g., a stateless REST API using JWT), we can disable it.
                                   - csrf.disable() disables Spring Security's CSRF protection.
                                   - After disabling CSRF, Spring will no longer require a CSRF token for POST, PUT, DELETE, or PATCH requests.
                          - How does Spring Security prevent CSRF attacks :
                                   - Spring Security prevents CSRF attacks by using CSRF Tokens.
                                   - Every authenticated user receives a unique random CSRF token.
                                   - Whenever the client sends a state-changing request (POST, PUT, DELETE, PATCH), the same token must be sent back.
                                   - Spring Security validates the token before processing the request.
                                   - If the token is valid, the request is allowed; otherwise Spring Security returns 403 Forbidden.
                          - How does CookieCsrfTokenRepository work :
                                   - CookieCsrfTokenRepository is a Spring Security implementation of CsrfTokenRepository.
                                   - Instead of storing the CSRF token in the HttpSession, it stores the token inside a browser cookie.
                                   - It is mainly used with React, Angular, Vue, and other Single Page Applications (SPAs). 
                          - What are the important CSRF components in Spring Security :
                                                       - CsrfToken : 
                                                               - Represents the CSRF token.
                                                               - It contains the generated token that the client must send with every modifying request.
                                                       - CsrfTokenRepository :
                                                                    Responsible for :
                                                                                 - Creating CSRF Token
                                                                                 - Saving Token
                                                                                 - Loading Token
                                                                    Common implementations
                                                                                 - HttpSessionCsrfTokenRepository
                                                                                 - CookieCsrfTokenRepository
                                                       - HttpSessionCsrfTokenRepository :
                                                               - Stores the CSRF token inside the user's HttpSession.
                                                               - JSP, Thymeleaf , Traditional Spring MVC
                                                       - CookieCsrfTokenRepository :
                                                               - Stores the CSRF token inside cookie XSRF-TOKEN
                                                               - Reads the token from header X-XSRF-TOKEN
                                                               - Best suited for React Angular Vue
                                                       - CsrfTokenRequestHandler :
                                                               - Makes the generated CSRF token available as a request attribute.
                                                               - It helps expose the token so it can be accessed by the application or included in the response.
                                                               - Common implementation: CsrfTokenRequestAttributeHandler
                                                       - CsrfFilter : 
                                                               - This is the main Spring Security filter responsible for CSRF protection.
                                                               - Responsibilities:
                                                                          - Intercepts every modifying request.
                                                                          - Extracts the CSRF token from the request.
                                                                          - Loads the expected token from the repository.
                                                                          - Compares both tokens.
                                                                          - Allows the request if they match.
                                                                          - Returns 403 Forbidden if they do not match.
                                               JWT  vs CSRF :
                                                               - If JWT is sent in the Authorization header:
                                                                           - Browser does NOT automatically attach the Authorization header.
                                                                           - An attacker website (evil.com) cannot automatically send the victim's JWT.
                                                                           - Therefore, CSRF attacks are generally NOT possible.
                                                                           - In this case, CSRF protection is usually NOT required.
                                                               - If JWT is stored inside a Cookie:
                                                                           - Browser automatically attaches the cookie with every request.
                                                                           - An attacker website can trigger requests that include the victim's cookie.
                                                                           - Therefore, CSRF attacks ARE possible.
                                                                           - In this case, CSRF protection IS required.
                                                               - Rule to Remember:
                                                                           - JWT in Authorization Header  →  No CSRF Protection Required (Generally)
                                                                           - JWT in Cookie               →  CSRF Protection Required

                Q1. Why Do We Need AOP? 
                          - Problem without AOP, the code for logging, security, and transaction management gets repeatedly mixed in with your core business methods. 
                            Your primary methods become cluttered and harder to read/maintain.
                          - Solution with AOP allows you to define this common logic in a single, reusable module called an Aspect.
                          - Spring then "weaves" (automatically inserts) this logic into your methods at the specified points, keeping your business logic clean.

                Q1. What is spring AOP ?

                            cross-cutting concerns.
                          - Cross-cutting Concerns: These are features required in many differéht parts of an application, but they are not the primary business logic
                             eg : Logging, Security, Auditing, Transaction Management, Caching etc.

                Q2. What are the key AOP terminology ?

                Q4. How spring AOP works ?
                          - The Magic of Proxies :
                                   - When we implement AOP inside our application using the Spring framework, it will intercept each method call and
                                     apply the logic defined in the Aspect. This process of inserting the Aspect logic in the target object is called Weaving.
                          - The Mechanism: Proxy Objects :
                          - It uses the Proxy Design Pattern :
                                           - Original Bean: You define your original business class (eg, contactController).
                                           - The Proxy: Spring does not give you a direct reference to your original ContactController bean. Instead, it wraps the
                                             target bean with a Proxy Object.
                                           - Interception: When you call a method on the controller, you are actually calling the method on the Proxy :
                                                                    - The Proxy intercepts the call.
                                                                    - The Proxy executes the Advice (your logging/security logic).
                                                                    - The Proxy then delegates the call to the actual method on the Target Object (your original bean).

                Q1. What is the N+1 Problem ?
                         - The N+I problem occurs when Hibernate executes one query to fetch parent entities and an additional query for each child collection, 
                           leading to performance issues.
                         - For example, with our DB schema, one companycan have many Jobs. default jobs are LAZY loaded:
                                                   @OneToMany (mappedBy = "company" )
                                                   private List<Job> jobs;
                         - How N+I problem occurs :
                               Step 1: Fetch Companies :
                                       - List<Company> companies = companyRepository.findAll() ;
                                       - Hibernate executes 1 query: SELECT * FROM companies;
                                       - Let's say: 30 companies are returned. So far -> 1 query
                               Step 2: Access Jobs for Each Company :
                                                  for (Company company : companies) {
                                                          company .getJobs ( ) . size ( ) ;
                                                   }
                                       - Now Hibernate does this:
                                                     SELECT * FROM jobs WHERE company_id = 1;
                                                     SELECT * FROM jobs WHERE company_id = 2;
                                                       ....
                                       - One query per company. If N = 30 companies, then total queries = 31 SQL quries.
                                       - This is called the N+l problem
                         - How N+l can be solved using batch fetch :
                                  - Hibernate notices: "You are loading the same association (jobs) repeatedly for many parents."
                                  - Instead of loading one company's jobs at a time, it groups multiple parent IDs together and 'fetchestheir children in a single query.
                                  - For example,SELECT' * FROM jobs WHERE company _ id .1N . 4, 5, 10) ;
                                  - Approach 1:
                                              - spring.jpa.properties.hibernate.default_batch_fetch_size = 50 
                                              - This is a global setting
                                              - Applies to all LAZY associations and entities
                                              - Hibernate will try to fetch up to 50 parent IDs at once
                                  - Approach 2:
                                              - @BatchSize(size = 50)
                                              - @OneToMany(...)
                                                @BatchSize (size= 50)
                                                private List<Job> jobs — new ArrayList<> ( ) ;
                                              - Applies batching only to this association Overrides the global, default
                                              - Useful when:
                                                        Some relations are accessed frequently Others should remain untouched
                       NOTE:- Batch fetching does NOT remove N+l entirely. Instead, it converts: N+l queries into 1 + (N / batchSize) queries. Always prefer JOIN
                              FETCH to completely solve N+l problem

                Q1. What Are Spring Boot Profiles?
                         - Spring Boot profiles allow us to create multiple configurations for different environments in a single application.
                         - Example environments:
                                         Development (dev)
                                         Testing (test)
                                         Staging (staging)
                                         production (prod)
                         - You can define different properties, beans, or behaviors for eachzénvironment.
                         - Why Do We Need Profiles :
                                 - Imagine an application running:
                                              On a developer's laptop -> uses local database
                                              On QA server -> uses test database
                                              On production -> uses secure production database
                                 - The same code but different configurations
                                 - Profiles avoid manual code changes between environments
                         - What Can You Change with Profiles :
                                 - You can customize almost anything!
                                              application.properties files
                                              Database connection
                                              API URLs
                                              Logging levels
                                              Bean creation (conditional beans)
                         - How to Define Profiles :

                                                                             application—<profile>.yml or application—<profile>.properties
                                 - For examples ,
                                          application-prod.properties   => for prod env/profile
                                          application-qa.properties   => for qa env/profile
                                 - The default profile is always active. Spring Boot loads all properties application.properties into the default profile.
                                 - We can activate a specific profile using spring.profiles.active property either by directly mentioning inside the corresponding file 
                                   or by providing externally using CLI, Env variables etc.
                                   Activate profiles via:
                                                      Command-line: --spring.profiles.active=prod
                                                      Environment variable: SPRING PROFILES_ACTlVE=prod
                                                      Application properties: spring.profiles.active=prod

                Q1. What is Conditional Bean Creation?
                       - Sometimes you want to create a bean only if a certain condition is true. Spring Boot provides powerful annotations to create beans conditionally.
                       - This is useful for:
                                         • Switching configurations
                                         • Enabling features for certain environments
                                         • Avoiding unnecessary beans in production
                       - @ConditionalOnProperty :
                                    - Create a bean "only if a property exists or has a specific value".
                                    - Example,
                                                @Bean
                                                @ConditionalOnProperty (
                                                                         name = "feature.enabled"
                                                                         havingValue = "true"
                                                                       )
                                                public MyService myService (){
                                                      return new MyService();
                                                 }
                                    - If you set feature.enabled=true in application.properties, the bean will be created.
                       - @Profile :
                                    - Create a bean only for a specific profile.
                                    - Example,
                                                @Profile("dev")
                                                @Bean
                                                public DataSource devDataSource(){
                                                     return new DevDataSource() ;
                                                }
                                    - This bean is active only when spring.profiles.active=dev
                       - @ConditionaIOnMissingBean :
                                    - Create a bean only if the bean does not already exist.
                                    - Example,
                                                @Bean
                                                @ConditionalOnMissingBean
                                                public MyService myService(){
                                                      return new MyService();
                                                }
                                    - Useful for providing default beans that users can override.
                       - @ConditionalOnClass :
                                    - Create a bean only if a specific class exists in the classpath.
                                    - Example,
                                                @Bean
                                                @ConditionalOnC1ass(name = "com.example.SomeLibrary")
                                                public MyLibraryBean myLibraryBean(){
                                                     return new MyLibraryBean();
                                                }
                                    - Great for auto-configurations.

                    NOTE:
                        Benefits of Conditional Beans :
                                                   • Clean & flexible configuration
                                                   • Activate features only when needed
                                                   • Reduce memory and startup time
                                                   • Avoid duplicate beans
                        The above concepts applicable for stereotype annotations as well.

                Q1. WHAT IS OBSERVABILITY ?
                        - Observability is the ability to understand the internal state of a system by observing its outputs. 
                        - In today's cloud-native world, observability is essential. 
                        - The three pillars of observability are:
                                    - Metrics: 
                                            - Metrics tell you how your application behaves.
                                            - Metrics are quantitative measurements of the health of a system.
                                            - They can be used to track things like CPU usage, memory usage, and response times.
                                    - Logs: 
                                            - logs reveal what the application is communicating at every step. 
                                            - Logs are a record of events that occur in a system.
                                            - They can be used to track things like errors, exceptions, and other unexpected events.
                                    - Traces: 
                                            - traces show how requests move across classes.
                                            - Traces are a record of the path that a request takes through a system. 
                                            - They can be used to track the performance of a request and to identify bottlenecks(rukawat).
                              NOTE:- By collecting and analyzing data from these three sources, you can gain a comprehensive(poora aur detailed) understanding of the 
                                     internal state of your backend application. This understanding can be used to identify and troubleshoot problems, 
                                     improve performance, and ensure the overall health of your system.
                        - Spring Boot treats observability as a first-class feature, not an afterthought. 
                        - With Spring Boot 4.0:
                                       - Observability setup is simple
                                       - Uses industry standards
                                       - Avoids vendor lock-in
                                spring—boot—starter—openteIemetry(One Starter to Rule Them All)
                                       - New official starter in Spring Boot 4.0. Available directly from start.spring.io
                                       - Automatically wires Metrics, Traces, OTLP export
                                       - This is the recommended and preferred way to enable observability in Spring Boot.
                                       - The OpenTelemetry starter brings together:
                                                                           - OpenTelemetry API
                                                                           - Micrometer -> OpenTelemetry bridge
                                                                           - OTLP exporters for metrics & traces
                                                                           - Spring Boot auto-configuration
                                                                           - No manual wiring
                                                                           - NO vendor-specific code
                        - WHAT IS OpenTeIemetry ?
                                   - OpenTelemetry is an observability framework and toolkit designed to facilitate the Generation, Export, Collection of 
                                     telemetry data such as traces, metrics, and logs.
                                   - The name OpenTelemetry is a combination of Open + Telemery
                                   - The word OPEN highlights that the project is open-source and vendor-neutral. Telemetry comes from the Greek roots TELE (remote) 
                                     and METRON (measure). In software, it refers to the data collected from your applications to monitor their health from a distance.
                                   - We can use OpenTelemetry with different observability tools such as:
                                                                                                        Grafana
                                                                                                        Prometheus
                                                                                                        Jaeger 
                                                                                                        and many commercial tools.
                                   - OpenTelemetry itself is not a dashboard or storage system.It mainly helps us collect and send telemetry data.
                                   - Its main goal is to make it easy to add monitoring to applications, regardless of:
                                                                                                            Programming language
                                                                                                            Infrastructure
                                                                                                            Runtime environment
                                   - Simple Flow :
                                                                Application 
                                                                    ↓ 
                                                                OpenTelemetry 
                                                                    ↓

                                                                    ↓ 
                                                                Sends the data 
                                                                    ↓
                                                                Grafana / Jaeger / Prometheus / Other Tools 
                                                                    ↓
                                                                We monitor the application

                                   - Telemetry and Its Components :
                                                            - Micrometer Metrics → application ke metrics collect/record karta hai.
                                                            - Micrometer Tracing → application ki requests/traces ko track/instrument karta hai.
                                                            - Logs → generally SLF4J + Logback jaise logging frameworks handle karte hain.
                                                            - OpenTelemetry → in telemetry types ke liye open standard/ecosystem provide karta hai.
                                                                                   Telemetry
                                                                                      │
                                                                                      ├── Metrics → Micrometer Metrics
                                                                                      │
                                                                                      ├── Traces  → Micrometer Tracing
                                                                                      │
                                                                                      └── Logs    → SLF4J + Logback
                        - Implementing Observability in Spring Boot :

                                                             - It provides a standard way to work with telemetry data, such as:
                                                                                                                             Metrics
                                                                                                                             Traces
                                                                                                                             Logs

                Q1. What are the different ways to consume external REST APIs in Spring Boot?
                          - There are various ways to call external REST APIs in Spring Boot:
                                                                                       RestClient (Synchronous)
                                                                                       HTTP Service Client (@HttpExchange) (Declarative Client)
                                                                                       WebClient (Reactive & Non-blocking) 
                                                                                       OpenFeign (Declarative Client for Microservices)
                        Explain RestClient ?
                          - RestClient is an interface in the Spring Framework.
                          - Introduced in Spring Framework 6.1.
                          - Used to consume external REST APIs.
                          - It is a synchronous (blocking) HTTP client.
                          - Provides a fluent API for creating HTTP requests.
                          - Recommended replacement for RestTemplate in new Spring Boot applications.
                          - Supports HTTP methods like GET, POST, PUT, DELETE, and PATCH.
                          - Instances are created using RestClient.create() or RestClient.builder(), not by using new.
                          - look code in notes.
                          NOTE:- Website for fake API :  https://jsonplaceholder.typicode.com/

                      Explain HTTP Service Client ?
                          - HTTP Service Client is a declarative HTTP client provided by the Spring Framework.
                          - Introduced in Spring Framework 6.
                          - Used to consume external REST APIs by defining Java interfaces.
                          - Uses the @HttpExchange annotation on interfaces and methods.
                          - Spring automatically creates the implementation at runtime.
                          - Eliminates boilerplate code compared to RestClient.
                          - Supports HTTP methods like GET, POST, PUT, DELETE, and PATCH.
                          - Can internally use RestClient (synchronous) or WebClient (reactive) as the underlying HTTP client.
                          - Best suited when working with well-defined external APIs.
                          - How HTTP Service Client works :
                              - STEP 1 :
                                      - @HttpExchange is the entry point.
                                      - Eg : @HttpExchange 
                                             public interface TodoService
                                      - Marks interface as an HTTP client.
                                      - Spring generates a runtime proxy.
                                      - Methods become HTTP calls.
                              - STEP 2 :
                                      - HTTP Methods Mapping with Exchange Annotations like :
                                                                                          @GetExchange
                                                                                          @PostExchange
                                                                                          @PutExchange
                                                                                          @DeleteExchange 
                                     - look code in github.

                Q1. If an API is taking too long to respond, what steps would you take to troubleshoot and improve its response time?
              - Troubleshooting a Slow API Response :
                       - Step 1 — Identify Where the Time Is Being Spent :
                                     - First, measure the total API response time.
                                     - If the API is taking too much time, first identify which part of the request is slow.
                                     - Do not optimize blindly. First identify the actual bottleneck.
                                     - Where to check :
                                           - API Client:
                                                 - Postman
                                                 - Browser Developer Tools
                                                 - cURL
                                                 - Check the total response time of the API.
                                           - Application Logs:
                                                 - Check the Spring Boot application logs.
                                                 - Check whether any operation is taking unusually long.
                                                 - Check errors, warnings, database calls, or external service calls.
                                           - Observability Backend:
                                                 - Grafana can be used to monitor metrics, logs, and traces.
                                                 - OpenTelemetry can collect and send telemetry data.
                                                 - Micrometer can provide application metrics.
                                                 - Distributed tracing can show the complete request flow.
                                     - If distributed tracing is enabled:
                                           - Use the Trace ID to find the complete request.
                                           - Search for the Trace ID in the observability backend such as Grafana.
                                           - Open the corresponding trace/span.
                                           - Check how much time each operation takes.
                                     - Example:
                                           - API:
                                                 - GET /orders/101
                                           - Total response time:
                                                 - 940 ms
                                           - Trace:
                                                 - Controller       → 10 ms
                                                 - OrderService     → 20 ms
                                                 - MySQL Query      → 850 ms
                                                 - Payment Service  → 50 ms
                                                 - Response         → 10 ms
                                     - From the trace, we can identify that the MySQL query is the bottleneck.
                       - Step 2 — Check Database Performance :
                                     - If the trace shows that the database operation is taking too much time, investigate the database.
                                     - Where to check :
                                           - Application Logs:
                                                 - Check the SQL query being executed.
                                                 - Check whether the same query is executed multiple times.
                                           - Database:
                                                 - Check query execution time.
                                                 - Check indexes.
                                                 - Check JOIN operations.
                                                 - Check query execution plan using EXPLAIN.
                                                 - Check whether a large amount of data is being scanned.
                                           - JPA / Hibernate:
                                                 - Check for N+1 query problems.
                                                 - Check entity relationships and fetch strategies.
                                                 - Check whether unnecessary data is being fetched.
                                     - Check:
                                           - Whether the SQL query is slow.
                                           - Whether proper indexes are available.
                                           - Whether expensive JOIN operations are being performed.
                                           - Whether unnecessary columns are being fetched.
                                           - Whether pagination is being used.
                                           - Whether N+1 queries are occurring.
                                     - Example:
                                           - SELECT * FROM orders;
                                           - If the orders table contains a large number of records, fetching all records can be expensive.
                                     - Better approach:
                                           - Use pagination:
                                                 - Page 1 → 20 records
                                                 - Page 2 → 20 records
                                                 - Page 3 → 20 records
                       - Step 3 — Check External API / Microservice Calls :
                                     - If the trace shows that another microservice is taking too much time, investigate that service.
                                     - Example:
                                           - Order Service
                                                 ↓
                                           - Payment Service
                                                 ↓
                                           - Notification Service
                                     - Where to check :
                                           - Distributed Trace:
                                                 - Find the span representing the external service call.
                                                 - Check the duration of that span.
                                                 - Use the Trace ID to follow the request across microservices.
                                           - Calling Service:
                                                 - Check Feign / RestClient / WebClient call time.
                                                 - Check timeout configuration.
                                           - Called Service:
                                                 - Check the called service's logs.
                                                 - Check its database queries.
                                                 - Check its own downstream API calls.
                                     - Check:
                                           - Feign / RestClient / WebClient call time.
                                           - Network latency.
                                           - External service response time.
                                           - Timeout configuration.
                                           - Unnecessary sequential calls.
                                     - If independent operations are performed sequentially:
                                           - A → 2 seconds
                                           - B → 2 seconds
                                           - C → 2 seconds
                                           - Total ≈ 6 seconds
                                     - If these operations can safely run in parallel:
                                           - max(2, 2, 2) ≈ 2 seconds
                                           - This can reduce the overall response time.
                       - Step 4 — Check Java / Spring Application Code :
                                     - If the database and external services are not the bottleneck, investigate the application code.
                                     - Where to check :
                                           - Distributed Trace:
                                                 - Check the span representing the application/service processing.
                                           - Application Logs:
                                                 - Check timestamps before and after expensive operations.
                                           - Application Metrics:
                                                 - Check CPU usage.
                                                 - Check memory usage.
                                                 - Check JVM metrics.
                                                 - Check garbage collection activity.
                                           - Profiler:
                                                 - For deeper investigation, use a Java profiler such as:
                                                       - Java Flight Recorder (JFR)
                                                       - VisualVM
                                                       - IntelliJ Profiler
                                     - Check:
                                           - Unnecessary loops.
                                           - Large collection processing.
                                           - Expensive calculations.
                                           - Repeated database calls.
                                           - Repeated calculations.
                                           - Unnecessary object creation.
                                           - Serialization / deserialization time.
                       - Step 5 — Implement Caching Where Appropriate :
                                     - If the trace shows that the same database data is repeatedly fetched and the data does not change frequently, consider caching.
                                     - Where to check :
                                           - Application code:
                                                 - Identify frequently accessed methods/data.
                                           - Metrics:
                                                 - Check cache hit and miss behavior if cache metrics are available.
                                           - Cache backend:
                                                 - If Redis is used, monitor Redis performance and response time.
                                     - General flow:
                                           - Request
                                                 ↓
                                           - Cache
                                                 ↓
                                           - Cache Hit → Return data quickly
                                                 ↓
                                           - Cache Miss → DB → Store in Cache → Return data
                                     - Spring Cache example:
                                           - @Cacheable("products")
                                           - public Product getProduct(Long id) {
                                           -     return repository.findById(id).orElseThrow();
                                           - }
                       - Step 6 — Use Pagination for Large Responses :
                                     - If the API returns a very large amount of data, check the response size and database query.
                                     - Where to check :
                                           - Postman / Browser:
                                                 - Check response size and response time.
                                           - Database:
                                                 - Check how many records are being fetched.
                                           - Application:
                                                 - Check whether pagination is implemented.
                                     - Example:
                                           - GET /users
                                           - If this returns 5 lakh users, the API can become slow.
                                     - Better approach:
                                           - GET /users?page=0&size=20
                                           - GET /users?page=1&size=20
                                     - Pagination reduces:
                                           - Database processing.
                                           - Memory usage.
                                           - Network payload.
                                           - Serialization time.
                       - Step 7 — Check Metrics in Grafana :
                                     - Metrics help identify whether the application has a performance or resource problem.
                                     - Where to check:
                                           - Grafana Dashboard.
                                     - Check:
                                           - API request count.
                                           - API response time / latency.
                                           - Error rate.
                                           - CPU usage.
                                           - Memory usage.
                                           - JVM metrics.
                                           - Database connection pool metrics.
                                           - HTTP client metrics.
                                     - Example:
                                           - If API latency suddenly increases:
                                                 - Check CPU.
                                                 - Check memory.
                                                 - Check database metrics.
                                                 - Check external service metrics.
                                                 - Then open the corresponding trace.
                       - Step 8 — Use Distributed Tracing to Find the Exact Bottleneck :
                                     - Tracing is especially useful in microservices because one API request can travel through multiple services.
                                     - Example:
                                           - Client
                                                 ↓
                                           - API Gateway
                                                 ↓
                                           - Order Service
                                                 ↓
                                           - Payment Service
                                                 ↓
                                           - Database
                                     - Use the Trace ID to follow the complete request.
                                     - In Grafana:
                                           - Search / open the trace using the Trace ID.
                                           - Inspect each span.
                                           - Compare the duration of each span.
                                           - Identify the span with unusually high latency.
                                           - Investigate the component represented by that span.
                                     - Example:
                                           - Trace ID: abc123
                                           - API Gateway      → 15 ms
                                           - Order Service    → 25 ms
                                           - Database Query   → 850 ms  ← Bottleneck
                                           - Payment Service  → 40 ms
                                     - Therefore:
                                           - Do not optimize API Gateway or Payment Service.
                                           - Investigate the database query first.
                       - Step 9 — Verify the Optimization :
                                     - After fixing the bottleneck, measure the API again.
                                     - Before optimization:
                                           - API response time → 940 ms
                                     - After optimizing the database query:
                                           - API response time → 150 ms
                                     - Compare:
                                           - Response time
                                           - Database query time
                                           - External service time
                                           - CPU / memory usage
                                           - Error rate
                                     - Confirm that the optimization actually improved the API.
